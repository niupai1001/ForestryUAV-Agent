# 林业遥感 Agent 真值评测执行计划

本文定义下一轮评测的题目来源、评分规则、实施顺序和验收条件。现有合成任务与工程测试继续用于回归，但不能替代这里的领域能力成绩。

## 1. 要回答的问题

1. Agent 能否从公开航摄影像和空间数据交付正确结果？结果质量达到什么水平？
2. 失败来自领域算法、任务理解、工具调度、运行环境，还是结果核验？
3. 在相同语言模型和领域资源下，当前 Harness 与参考实现的差距是多少？不同完整系统的实际表现又是多少？

先测**同模型、同领域资源的调度能力**，再测**各产品原生配置下的完整系统能力**。两组成绩分开报告。GPT 是模型系列；比较 GPT 对调度的影响时应固定 Harness、替换明确版本的 GPT 模型，不能把“GPT”视作一个固定 Agent 实现。

## 2. 数据、真值与题库

### 2.1 首轮数据

| 来源 | 首轮用途 | 真值及限制 |
|---|---|---|
| [OAM-TCD](https://huggingface.co/datasets/restor/tcd/blob/main/README.md) | 航空 RGB 树冠提取、基于给定掩膜的覆盖统计 | 官方测试划分含影像与人工标注。标注区分单木和树冠群；首轮合并为“树冠/非树冠”，不据此评估闭合林冠单木计数、生物量或碳储量。 |
| [GABench](https://github.com/GeoX-Lab/GABench) | 非卫星依赖的多步骤 GIS 分析 | 只选输入完整、结果能够独立重算的题目。原项目的轨迹和视觉评分可供诊断，最终结果由本项目的确定性检查判定。 |

TreeSatAI 航空影像树种分类列为第二批扩展；BAMFORESTS 单木和 FOR-instance UAV 激光雷达暂不进入首轮。它们对应不同预测目标，不能与树冠 IoU 混算。

OAM-TCD 固定为 `restor/tcd` 的提交 `d97d4da0ebbb6e249ae95ac5e19656babd972eb2`，只使用 CC-BY 4.0 主数据仓。测试文件 `data/test-00000-of-00001.parquet` 的 SHA-256 为 `5c10ac4cb8afaf18dae5aad5b22cc86bb80977116a8bcd8c16d41ae48b9b13cf`。当前已在 `data/oam_tcd/` 下载并校验该文件：439 个测试样本，来自 55 个 `oam_id`。原始资料及标注的许可和来源要随成绩保存。

### 2.2 首轮题目

正式试点共 **18 题，每题独立运行 3 次**；每个被测配置最多 54 次试验。这是诊断性基线，不是公开排行榜或产品认证。

| 题组 | 数量 | Agent 可见输入 | 预期交付 |
|---|---:|---|---|
| 树冠提取 | 6 | OAM-TCD RGB GeoTIFF | 与输入网格对齐的 0/1 树冠 GeoTIFF、覆盖率、结果说明 |
| 树冠空间统计 | 6 | 来自**另外六个原始影像来源**的给定树冠掩膜 | 树冠像元数、有效像元数、覆盖率 JSON；后续扩展独立的分区/裁剪题 |
| GIS 多步骤分析 | 6 | 从 GABench 筛出的输入数据与自然语言目标 | 题目要求的矢量、栅格或统计结果及说明 |

树冠提取与空间统计不共用 `oam_id`，避免统计题把提取题的答案暴露给 Agent。不同测试任务在独立工作空间运行；正式试点标签及评分器不能挂载到 Agent 工作空间、工具搜索目录或知识库。公开数据的真值本身并非秘密，因此报告中须说明：此隔离防止运行时直接读取评分答案，不能证明模型预训练阶段从未见过数据。

当前 `evaluation/grounded_v1/oam.py` 已从固定测试文件中按固定种子选出 12 个不同 `oam_id`，生成 6 道提取题和 6 道统计题，并将公开输入和私有真值分开放置。`data/oam_tcd/grounded_v1_private/manifest.json` 是当前试点的样本清单。此步骤**没有**建立评分器，也没有得到 Agent 成绩。

在运行正式试点前，先人工复核这 12 个样本的有效区域、标注编码和来源分布；如需换题，先更改题库版本并重新冻结，不能见到某个 Agent 的成绩后再挑选样本。另从官方训练划分抽取来源互不重叠的开发题，专用于调试输入、评分器和预算，开发题不进入正式分母。

GIS 六题的确定方法：枚举 GABench 的非卫星任务，筛掉缺输入、依赖在线私有服务或不能程序化判定最终结果的题；按矢量处理、栅格处理、组合分析各取两题。发布筛选台账，列出候选 ID、排除原因、参考结果的独立复算方法、许可和最终 ID。六题及版本一经冻结，各系统运行同一组题。若不足六题满足条件，停在“题库不足”，不悄悄换成合成题；此时先公布已完成的 OAM 分组，不发布 18 题总体成绩。

## 3. 评分标准

所有检查在运行前随题目冻结。每次试验由独立评分器读取交付产物和公开轨迹；Agent 在回复中自称“通过”不是证据。

### 3.1 结果质量

**树冠提取**：在冻结的有效像元域上以非零树冠为前景，主指标为 `IoU = TP / (TP + FP + FN)`，同时报告 Precision、Recall、F1，以及覆盖率绝对误差（百分点）。真值与预测均无前景时 IoU 记 1；仅预测有前景时记 0，并单列空前景样本数量。按原始影像来源汇总，来源等权；官方指标单独展示，不把本项目子集成绩当成 OAM-TCD 官方排行榜成绩。

**统计与 GIS 题**：每题所有必需断言均通过记 1，否则记 0。逐题列出数值误差与失败检查。数值先检查量纲、分母、有效区和定义，再按 `|预测－真值| ≤ max(绝对容差, 相对容差 × |真值|)` 判定；每题明确单位、具体容差及其依据。离散类别与对象 ID 精确核对；地理坐标参考按语义等价、网格和仿射变换按题目精度核对。真实地表面积与投影平面像元面积不得混称；首批覆盖率题只要求无量纲百分比和像元数量。

### 3.2 有效交付

`V=1` 当且仅当必需文件齐全、可读、类别编码正确、GeoTIFF 空间网格满足要求、报告关键数值与文件一致、在预算内完成且无已证实的测试标签违规使用；已验证不满足则 `V=0`。证据采集器或评分器损坏记 `unknown`，不默认为 0 或 1。

树冠组同时报三项：有效交付率、有效交付时的平均 IoU，以及 `100 × mean(V × IoU)` 的端到端树冠得分。统计和 GIS 组报严格任务成功率。三个组分开呈现，不拼一个会掩盖任务差异的“智能总分”。未完成与已知超时保留在预定分母中。

### 3.3 过程诊断与效率

可观察的过程检查包括：输入和分析范围是否选对、方法是否适用于数据、步骤依赖是否满足、关键参数是否正确、错误后是否有效恢复、是否核验产物、是否过早结束、结论是否受产物支持。每项为 `pass / fail / unknown / not_applicable`，关联事件或产物证据。允许不同的正确工具路线；不要求工具名称和完整调用顺序与某份示范轨迹一致，不评分隐藏思维链。

单列总耗时、模型调用次数、token、实际可确认费用、CPU/GPU 用时、无效重试与等待次数。失败试验的时间和成本同样计入。三次运行逐次报告，不挑最佳一次；小样本只给原始结果和波动，不做夸大的总体可靠性声明。

借鉴依据：[Earth-Agent 的工具与端到端评测](https://github.com/opendatalab/Earth-Agent)、[RS-Agent 的规划实验与工具说明](https://github.com/IntelliSensing/RS-Agent)、[OpenAI 的轨迹评分说明](https://developers.openai.com/api/docs/guides/trace-grading)、[Anthropic 对任务、轨迹和最终环境状态的定义](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)。RS-Agent 仓库的默认占位工具只可用于规划实验，不能据此认定完成了真实遥感推理。

## 4. 实施顺序、接口与验收

### 阶段 A：题库与评分器

1. 校验 OAM-TCD 样本和标签含义；建立开发题及其独立来源。完成 GIS 候选筛选台账，冻结六题 ID 与输入版本。
2. 为每题建立 `TaskSpec`：题目、公开输入、预期交付、评分规则、预算和可用资源。私有真值另存；公开目录仅包含题目允许的输入。
3. 实现只读评分器：读取 `TrialBundle`（配置快照、轨迹、产物及用量），输出 `GradeReport`（质量、交付、过程检查、失败原因和证据）。评分器不得调用被测 Runtime 的同一业务函数生成标准答案，也不得在宿主机执行 Agent 产出的代码。
4. 用开发题和反例测试验证评分器：掩膜整体平移、CRS 错误、掩膜全零、类别编码错误、统计分母错误、遗漏文件、旧产物复用及报告与文件矛盾均应被识别；正确的替代执行路线不能被误罚。通过后冻结规则版本。

阶段 A 的验收是：18 题均有独立真值和可运行评分规则；反例测试通过；评分器对同一证据重复运行产生相同结果。如 GIS 来源不足，只验收 OAM 的 12 题并明确缺口。

### 阶段 B：控制资源的 Harness 对照

先运行当前 Harness 与一个基于已使用 SDK 的最小参考配置。两者固定同一 LLM 版本、领域模型和权重、预装库、输入、权限、预算、运行环境及题目顺序；按题交错运行。参考配置仅保留必要的工具循环、文件/代码执行接口和轨迹采集，不再造一套业务 Runtime。记录每次试验的模型、提示词、工具定义、代码和环境版本。

若 Claude Code、Earth-Agent 或 RS-Agent 可在相同题目上实际运行，再作为附加系统；无法提供等价资源时明确标注差异。模型不同的运行只解释为完整系统表现，不归因为 Harness 本身。

阶段 B 的验收是：每个完成对照的配置有 54 个预定槽位的成绩或明确的失败/未知原因；分题、分组和逐次证据可复算；对照表写清楚共享与不共享的资源。

### 阶段 C：原生能力对照与改进决策

各系统可使用原生模型、检索和领域工具，仍用同一已冻结题目与评分器。单独报告完整系统成绩、成本和可复现配置。依据失败频率和影响，形成下一轮改进清单：每项明确对应题目、轨迹证据、拟修改的模块以及复测方法。

优先处理数据泄露或评分错误，再处理实际阻断任务的运行缺陷，随后处理高频领域失败与成本问题。随机森林例子只保留为通用执行回归，不纳入领域能力分母。观察/多模态、单木和激光雷达能力待本轮证据出来后再决定是否扩展。


下一动作是完成阶段 A。阶段 A 给出可复算的题目与评分器之后，才有可靠依据讨论 Harness 调整、工具增添或模型替换。
