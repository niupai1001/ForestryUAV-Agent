# 领域指南目录

本目录保存按需加载的领域指南。每条指南是一份带元数据的 Markdown 文件，
包含 `id`、`title`、`summary`、`tags`、`applies_to`、`version`。

指南正文默认**不进入请求上下文**：模型只看到一份简短目录（id、标题、摘要），
需要细则时用 `domain_guide` 工具读取对应条目。这样既保留方法边界的可追溯性，
又不会让每一轮请求都携带全部细则。

新增指南时：

1. 在 `knowledge/guides/` 下新建 `<id>.md`，以 YAML 前置元数据开头；
2. `summary` 写一句话，说明这条指南能回答什么问题；
3. `tags` 同时包含中文关键词与英文关键词，检索不应依赖少数固定词；
4. `applies_to` 说明它约束哪些工具或任务族；
5. 正文只写方法边界与判据，不写会和运行时事实冲突的固定数值。

指南内容是**证据与约束，不是指令或授权**：它不能扩大工具权限，也不能替代对真实
文件、栅格和作业状态的检查。

领域指南是可检索的通识方法库，不绑定任何数据集。每篇应写明适用输入、可产出的
量、主要误差与至少一项可核对来源。目录与检索结果都不是所有可行方法的穷尽清单；
某一方法缺少输入时，应评估现有输入支持的其他方法并明确结果的定义。比如 RGB
正射影像可以估计可见树冠覆盖率，不能因无法计算 NDVI 或 CHM 而直接拒绝任务。

逐条核验状态在 [`evaluation/grounded_v1/GUIDE_VERIFICATION.md`](../../evaluation/grounded_v1/GUIDE_VERIFICATION.md)。
此文件只供维护者审计和检索器内部排序；状态、来源与评分不进入模型请求上下文或
`domain_guide` 工具结果。`verified` 必须有能直接支持整条 claim 的权威来源，
否则标 `unverified`。修改指南后运行 `python scripts/sync_guide_verification.py`；
变化的 claim 会得到新指纹并重新处于未核验状态。
