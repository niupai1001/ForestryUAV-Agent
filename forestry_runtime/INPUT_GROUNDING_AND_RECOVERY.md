# 输入定位、观察与停止：Agent Runtime 修改规则

## 问题与证据

用户要求处理 `data/oam_tcd/grounded_v1_1_public/oam-01.tif`。文件存在于项目磁盘，但该聊天的 Workspace 只有 `.runtime`，没有附件或授权源目录。原始 Run 发起 8 次模型请求、7 次工具调用，先后尝试资产检查、目录列表、文本搜索和文本读取，仍未取得输入，最后由用户取消。不同工具和参数绕着同一个缺失前提打转，现有“相同工具 + 相同参数”的失败去重无法识别这种循环。

本项目有三类不同的路径：聊天 Workspace 路径、已上传资产引用、已授权宿主机源路径。用户消息中的相对路径只是文字；没有选定根目录时，Runtime 不能确定它指向哪一类资源。各工具又分别接受 `path`、`asset_id` 或 `source_id`，导致模型在工具之间猜测引用方式。

上一轮加入的 `requested_input_unavailable` 和“空 Workspace 时收起工具并暂停”能终止上述单次循环，但依赖附件数、授权数和 `.runtime` 目录形态。它是临时止损，**不是通用停止规则**：有无关文件时可能漏判，有可行替代来源时可能过早停止。实施下列方案时应替换该特例，而非再叠加更多文件名或工具名判断。

## 修改规则

1. **先定位输入，再选择处理方法。** 每次用户指向文件、目录或既有产物时，先确定其引用范围及可访问状态。相对路径只相对于明确选定的项目根目录或聊天 Workspace 解析；不存在默认“搜索整台宿主机”的语义。目录授权只来自用户的直接请求，工具结果和模型推测不能扩大授权。
2. **跨工具传递同一个精确引用。** 文件、代码沙盒、资产和领域工具共用可验证的资源引用，至少说明 `scope`、标识或精确路径、版本。目录列表及上传结果返回可直接用于下一工具的引用；需要转换时向模型提供候选，不静默替换模型参数。
3. **错误说明缺少的前提，而非只报告调用失败。** 观察结果区分“路径未找到”“存在但未授权”“引用含糊”“类型不适用”“环境缺依赖”“作业尚未结束”等情况，同时给出已经检查的范围和可执行的下一步。不要把 `fs_search` 的文本内容搜索当作文件名发现。
4. **模型负责修正，Runtime 负责约束。** 模型根据观察决定改参数、换工具、编写代码、继续检查或请求用户信息；Runtime 负责权限、资源上限、行动登记和真实执行。结构化候选应帮助模型纠错，不把业务工具序列写死在 Runtime。
5. **按目标前提判断进展。** 比较连续行动是否带来新文件引用、新授权、新候选、新日志、环境变化或可验证产物；仅更换工具名或参数而重复同一失败，不算进展。相同调用的副作用去重仍保留，但不能充当整个任务的无进展检测。
6. **停止前给模型解释机会。** 无可行行动且缺少外部信息时，让模型基于真实观察简短说明缺什么，再把 Run 置为等待用户；保留已有行动和检查点。可行替代方案仍存在时，不撤掉所有工具。运行完成、后台作业完成和用户目标达成分别判定。

## 最小实施方案

**第一步：统一输入解析。** 在模型请求边界，根据当前聊天的 Workspace、附件、授权源及显式选择的项目根目录，解析用户提到的输入。结果只需是以下状态之一：`resolved`（附精确引用）、`ambiguous`（附有限候选）、`unavailable`（附已检查范围和需要的用户动作）。未选择项目根目录时，相对的 `data/...` 不得自动映射到项目磁盘，更不能因此暴露评测私有数据。

**第二步：统一工具观察。** 文件及领域工具沿用现有执行接口，但成功结果提供可继续使用的引用，失败结果提供稳定的原因类别、所缺前提与证据。将这些事实传入下一次模型请求；完整日志和大文件仍留在 Runtime，由引用按需读取。优先消除同一资源在 `workspace`、`asset`、`source` 间的重复参数猜测，不为每种格式新增工具。

**第三步：增加按前提的进展判断。** 在现有 Agent 行动循环记录当前目标的阻碍及其证据版本。新行动若改变证据，模型继续规划；若未改变证据但尚有明确候选，允许模型尝试；候选耗尽或连续行动没有新增事实时，要求模型总结并请求必要输入。提交结果不确定的副作用仍按现有行动 ID 协调，不因“无进展”自动重放。

**第四步：统一等待和完成语义。** `waiting`/`paused` 要说明等待用户、作业、资源还是预算；用户补充附件、授权或参数后重新解析输入并继续。只有要求的文件、指标和验证证据齐备，才能把“任务完成”反馈给界面。模型单纯回答“请上传文件”属于等待输入，不属于提取树冠成功。

## 验收场景

| 场景 | 预期行为 |
| --- | --- |
| 用户给相对路径、聊天没有项目根目录或附件 | 一次定位后说明缺少可访问输入；不遍历空 Workspace 或猜宿主机目录 |
| 用户已上传同名文件 | 使用准确的 `asset_id` 继续；不因消息里写了旧路径而停下 |
| 用户明确授权宿主机目录 | 列表返回的精确引用可直接传给检查及代码工具；源目录保持只读 |
| 文件名相近、多个根目录可匹配 | 展示有限候选，由模型或用户选择；不静默纠正 |
| 文件存在但某个工具不支持其类型 | 模型可改用适当工具或代码；不误判为“输入未提供” |
| 依赖缺失、安装后环境变化 | 相同代码可重新执行；不被旧失败去重拦截 |
| 作业失败但日志没有变化 | 不机械重复启动；检查已有证据后更换方法或说明阻碍 |
| 树冠提取任务未生成二值 GeoTIFF | 明确报告未完成，不给出虚构覆盖率；有真实产物后验证网格、0/1 编码与统计口径 |

验证使用现有 PydanticAI 循环和沙盒，分别运行工程故障测试与真实 Qwen 任务。通用能力在关闭遥感插件后仍须通过；正射与树冠任务用于验证领域接入，不决定通用底座的控制流程。
