# 隔离角色与冲突交付

H2按需要委派固定通用角色，不要求每个任务启动全部角色。每个AssignmentRequest明确目标、输入资源和产物子集；原生子循环有自己的检查点，应用保留权限交集、累计预算及独立输出路径。父对话和未授予的资源不进入子上下文，角色返回不能提交父级验收。

新任务冻结当时角色目录。子角色的`action.inspect`只允许自身run的动作，不能查看或复制父级、兄弟角色回执；还受任务能力上限限制。默认环境、数据、实验和质量角色具有这一能力，以便附加自己已读取来源的真实citation。此前默认目录缺少它，实际`write_file(citation_actions=...)`被权限交集拒绝。本次只补该目录能力，沿用原动作归属校验，没有改权限检查或原任务的冻结目录。

文件来源引用与产物/记忆标识分别保留。`citation_actions`只接收带顶层`citation`的已确认来源动作；产物读取的`artifact_id`/`sha256`和记忆的`memory_id`/版本应写在正文。实际v2质量角色曾把产物读取也放进引用映射，通用报错使它未能纠正。本次反馈明确指出无效字段及动作，说明移除该项并保留有效文档引用；跨任务、旧修订、失败和损坏来源继续拒绝。数据角色已交付的产物在同任务纠正后复用。

子角色执行成功表示完成了委派工作。候选主张正确与否须看独立检查和实际证据；质量角色可以成功完成检查，同时返回某项主张`failed`。协调者须读取角色产物，保留差异、条件、来源和局限，说明采用或拒绝的理由，最后交付实际报告。文件可读和角色成功状态不能替代语义验收。
