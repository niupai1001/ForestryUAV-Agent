# 修订后的实施基线 · 1.2

本项目独立重新开发，不复用或迁移旧 ForestryUAV-Agent 代码与数据。原始项目书副本为需求依据；本文件记录经审查及用户选择后的修订。中文为当前权威来源，英文译本共享版本号。

## 保留范围

R01–R16 与 U01–U08 保留。先交付完整通用 Agent 与可用本地 UI，再实施影像/LiDAR 两条真实流程，最后通过六组合、低资源与真实 ≥100 GB 规模验收。允许前期核验领域工具和公开数据可行性，不提前开发领域功能。

角色长期配置、按需隔离委派，不强制部门顺序。没有独立现场真值时，允许有明确支持和局限的内部检查产品，不声称已验证精度。绿色代理不能代替冠层覆盖。低资源硬件由用户在 pilot 后确定；未冻结及实测前，不宣布完整 V1。

## 必须修正的契约

1. 第 6 节节点改为行为职责，采用 PydanticAI/Harness 原生循环、检查点和压缩，不另建 LangGraph 循环。
2. 首次副作用前持久保存动作、attempt、输入和授权身份；完成调度器不是登记动作的前提。
3. 普通消息不改变任务规范修订；目标/输入/方法/约束变化使用独立 amendment。状态版本与规范修订分开。
4. 候选文件和清单先验证，形成验收记录后封存最终清单并发布，对账后提交终态。清单不递归哈希自身。
5. 统一指标字段 spatial_support_ref。外部类型只在真实边界增量添加，不预建每条记录的 service/repository。
6. WP 管实施，AC 管验收，DOM 映射 WP；通用和领域共用执行、资源、事件、报告和交付机制。
7. 框架记录模型历史/检查点；应用 SQLite 记录任务、授权、动作、作业、证据、验收。框架检查点不授予成功或权限。
8. 私密上下文产生的外传查询需范围授权；网页读取拒绝私有/回环地址及不安全重定向；报告预览隔离脚本和网络。
9. 公开/持久化输入拒绝多余字段；源数据只读；不接受模型制造的用户授权事件；取消以实际执行端回执为准。

## 实施批次

P0：修订和可行性；P1：真实 UI/模型/文件闭环；P2：受限执行与恢复；P3：完整通用产品；P4：影像；P5：LiDAR；P6：冻结实验、规模与发布。每批独立记录实现、验证、失败和证据，不以目录/截图/退出码代替行为验收。
