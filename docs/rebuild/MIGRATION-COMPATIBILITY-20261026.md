## 发布时的操作顺序与边界

现有CLI入口为`forestry-agent backup create|inspect|restore --config <配置> --path <独立目录>`；以cli.py当前参数为准。以下是操作方案，本轮没有操作生产库。

1. 确认实际服务、Worker及writer归属，暂停并对账所有未决副作用；关闭对应服务。备份会拒绝活跃执行。停服不能仅凭端口或状态文件推断。
2. 升级前在运行工作区外新目录create并inspect，保留旧版本源码/依赖/前端/配置身份。不要将工作区复制得来的绝对路径误当已迁址。
3. 需要回退时先停止新写入，再为发布后数据create并inspect；记录新增消息、Job、产物及其来源，不覆盖发布前备份。
4. 在根目录工作区锁持有期间，将现有.forestry和tasks整体移动到显式指定保留目录。移动前逐一验证解析后的源为该工作区两个目录，目标位于明确的保留根目录且不存在；不递归删除、不跨shell拼接移动。锁文件在工作区根，不能一起移动或删除。之后才restore发布前快照到原工作区路径。
5. 启用旧版本只使用与之匹配的旧快照，发布后新增数据仍保留。**未证明可把当前V2数据库直接交给历史旧版本运行。** 特别是job_deliveries的新状态presented/skipped/needs_attention及turn_continuations，不用降级删除/伪造consumed解决。
6. 需要重新使用发布后数据时，再停止/对账/备份回退期间产生的数据，整体保留旧工作区两目录，在同一根锁下restore发布后完整快照，并使用匹配V2版本。上述切回路径已有隔离证据。两条时间线若都新增数据，分别完整保留；目前没有自动合并，不承诺两条时间线同时可写或自动续接。

第4/6步的路径和归属必须在实际操作前具体化，不能照抄占位路径执行。原工作区路径是恢复前置条件；外部原文件不包含在备份中，需独立保留其可用性与版本。
