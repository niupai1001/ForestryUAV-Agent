## 补充待修问题：非JSON错误响应导致界面二次报错

- 用户报告（2026-10-21）：反复出现 `Unexpected token 'I', "Internal S"... is not valid JSON`。状态：待定位、待修复；本次仅补充问题记录，未修改代码或重新运行模型。
- 已知含义：客户端尝试将以 `Internal S` 开头的响应解析为JSON，解析失败。这通常意味着收到了纯文本的 `Internal Server Error`；具体HTTP状态码、请求接口、服务端异常及是否与300秒超时有关，尚未核实，不能仅凭这条提示确定。
- 影响：JSON解析错误掩盖真正的服务端错误，用户看不到请求失败原因，也难以判断是否还能继续发送消息。
- 定位要求：记录失败接口、HTTP状态码、响应Content-Type、脱敏后的有限响应片段及对应服务端异常/请求标识；区分应用接口失败、模型服务失败和网络中断，不自动将其归为模型超时。
- 修复要求：客户端读取响应时同时处理HTTP失败、非JSON正文和空正文，提供明确且有界的错误提示，不能因解析失败覆盖原始状态；服务端对未处理异常提供统一JSON错误结构，详细堆栈保留在日志中。错误发生后应结束等待状态，并允许适当的重试或继续对话，不能把失败响应当作成功答案。
- 定向验收：使用隔离接口夹具覆盖纯文本500、非JSON网关错误、空响应及原有JSON错误；界面应显示可理解的失败原因，不再暴露JSON解析异常，且能继续操作。不以重复真实模型或科学作业来验证错误展示。
