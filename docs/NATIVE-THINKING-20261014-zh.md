# 原生思考与界面收敛

依据：用户明确要求开启本地模型思考链，去除处理说明等无用要素。思考直接来自当前模型，不增加摘要、翻译或独立规划模型。

## 验证前记录

- 触发：当前兼容接口设为reasoning_effort=none；流处理忽略ThinkingPart；处理说明字段/拼接逻辑及report_progress工具与用户需求不符；空计划页仍展示。
- 影响：模型思考控制、独立思考流、回答后回看、移除说明和进度工具、按需Plan显示。
- 复用：已通过的直接回答、Markdown、附件/路径/目录、读图、停止续聊、科学计算与预算证据。
- 停止条件：新通道的定向软件检查、一次界面链及一次真实模型思考/回答分离通过后停止。保留首次失败，不重置历史预算或重做科学Job。

## 当前结果

**1.55，2026-10-15收口；已部署到原8769工作台。** 可用流程为：发送消息→独立观察模型原生思考流→收到完整Markdown回答→回答后展开思考；重新打开原会话仍可回看正常完成回复的思考。

| 项目 | 当前行为 |
|---|---|
| 原生思考 | 使用本机Ollama兼容接口支持的reasoning_effort，按模型实际声明的thinking能力及档位选择；本机large使用medium，布尔开关模型使用兼容接口的启用档。明确不支持思考的模型不强行启用。 |
| 流与保存 | 接收SDK的ThinkingPart/ThinkingPartDelta，经assistant.thinking.delta独立传到界面；正常完成时与回答分别保存。思考期间默认展开，完成后可点击“思考”回看。 |
| 成本与上下文 | 思考由当前同一次模型生成提供，没有摘要或翻译模型，也不为展示另发一次请求。原生思考本身占用该次生成的时间与token；不承诺零成本。历史思考仍保留在本地记录，兼容接口适配器不将这些ThinkingPart再发送到后续请求。 |
| 精简界面 | 移除“处理说明”“处理过程”“本次结果说明”及对应摘要拼接、字段和report_progress工具。真实错误、作业记录和需要处理的阻碍仍由原通道提供。历史数据库不改写，旧说明字段不再展示。 |
| 按需计划 | 简单问答、读取或单步操作直接执行。需要持续跟踪的分阶段任务由模型按需write_plan；有实际条目时才显示右侧“任务”并首次切换过去，不保留空计划页或说明栏。计划优先对应正在执行的回合，后续排队消息不抢走它。 |
| 既有边界 | 不更换模型权重，不调整应用32K窗口、4K输出预留、请求超时或累计预算。旧任务配置快照保留，当前实际请求采用新原生思考策略。联网搜索继续暂缓。 |

目前展示协调Agent的原生思考；独立子角色的思考未接入这个对话区。正常完成回复保存思考字段；中断时的已生成片段仍在事件记录/当前流中，不把它描述为已完成回复或保证所有中断片段成为历史消息。
