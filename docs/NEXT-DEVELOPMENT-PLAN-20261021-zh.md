## 1. 本阶段要交付什么

用户可以在同一个 Agent 中连续交流，上传文件、图片、文件夹或提供路径，由 Agent 自行选择读取和计算工具；执行过程中能看到模型接口实际返回的思考与工具进度，停止后能继续交流，重启后能接续已有作业，删除会话时能清理其所属数据。专业主线为正射多光谱与 PROSAIL LAI 的已有成果读取、核查和解释。

这轮研究中的 12 项任务是问题样本，不是产品需求的全部，也不是下一轮重跑队列。下一阶段围绕完整使用流程组织，发现新问题时补充对应故障类型的回归证据。

范围保持：点云后续开发暂缓；Agent 联网搜索与领域峰值资源/吞吐评估取消；正式重复、配对、消融与留出评估在阶段 3。开发时查阅互联网资料不改变产品联网功能的取消状态。

## 4. 技术方案：沿用框架，补齐边界

先复用 React/FastAPI、SQLite、现有 Jobs/容器执行及 Ollama/Qwen 的可用实现，通过明确接口重新组织核心。Pydantic AI/Harness 可以作为驱动实现保留，也可以在无法满足接口契约时替换；必要时可采用 DeepSeek Harness。用户已允许有依据的核心重建，不能把沿用旧框架作为硬约束。ODM/PROSAIL 的正确成果、用户数据及已验证科学实现继续复用。

职责收敛为：

1. **消息与附件层**：保存用户原消息、附件引用、正文和接口返回的思考块；输入框仅显示待发送内容。
2. **上下文层**：从历史、必要指令、工具目录和按需读取内容编译本轮输入。归档存储、UI 展示、模型上下文三者分开。
3. **编排层**：模型决定回答、工具调用或必要计划；沿用现有 Harness 能力，系统执行预算与状态约束。
4. **工具与 Jobs 层**：短读取直接返回；长计算登记持久 Job，输出文件引用，完成后按调用标识恢复。重复恢复不重复启动副作用。
5. **事件与恢复层**：以持久状态为依据，向前端推送有序事件，负责断线重放、取消确认和重启核对。

对专业工具按需加载是内部路由，不要求用户选择“通用/专业/仅回答”。思考展示使用模型服务实际提供的字段，不额外调用模型生成“思考摘要”。Plan 仅在任务需要且模型创建时显示。

## 5. 交付顺序与验收出口

### D0：纠正证据并建立可信诊断（先决条件）

**交付物：** 可追溯的历史试次清单、纠正后的研究结论、可信请求时间轴；这一项是工程基础，不冒充新增用户功能。

- 从研究库和现存记录恢复 29 个实例的身份、配置、失败层和干预。新试次按唯一 ID 追加，`task-NN.json` 仅作索引，不覆盖原记录。
- 修正 task03 oracle、task09 归因、task05 合成标签和 task12 人工裁决；评分规则变更对旧输出离线重评。
- 在 `client.py`、`agent.py` 及前端事件接收处关联 conversation/turn/request/tool_call/job 标识。区分连接建立、响应头、原始传输片段、有效思考/文本/工具片段、首屏呈现、终态。
- 首片段不能计入历史重放和框架合成事件；服务端用同一单调时钟，浏览器单独记录接收/呈现，不能直接相减不同时钟。
- 错误诊断改只读；日志按请求追加。核实串行化锁实际作用范围，不再把实例内锁称为数据库单连接。
- 运行前快照实际模型标识、服务上下文、thinking 档位、schema/指令版本、代码和配置摘要；执行时读取快照，避免全局设置中途漂移。

**出口：** 已有结果无需重跑即可正确分类；用确定性模拟流能定位“无响应头/有头无内容/有思考无正文/前端未显示”，故障不改变业务数据库。一次复核受影响项后冻结。

### D1：连续对话、原生流与停止后继续

**用户新增可用流程：** 提问→看到实际返回的思考/正文→停止→发送下一条→刷新回看，失败时能知道停在哪一层。

- 修复 provider→Harness→持久事件→前端的思考增量路径，正文按 Markdown 渲染。没有思考字段时显示实际等待状态，不伪造思考。
- 流片段分型、按序号去重。刷新重连只重放缺失事件，不重复触发模型请求；取消/超时产生明确终态并解除输入锁定。
- 保持当前单请求 300 秒上限作为待诊断基线，不以关闭思考或盲目延长超时宣称修复；发现具体服务层原因后，修改必须有对应证据。
- 停止响应与停止关联计算分别执行；界面可先显示“正在停止”，确认受影响作业停止或明确失败后再结束该操作。

**改动入口：** `client.py`、`agent.py`、`public_stream.py`、前端 `App.tsx`/`NativeThinking.tsx`/`api.ts`；复用现有 Markdown 与附件组件。

**出口：** 一次受影响的真实模型会话完成上述链路；断流、重连、重复终帧等边界用确定性模拟验证。失败只修失败层，不重复已通过的科学任务。

### D2：文件、批图与上下文预算

**用户新增可用流程：** 上传文档/一批图片/成果目录→Agent 选择所需内容→回答→追问；文件留在消息和会话资料中，不持续挤占每轮上下文。

- 输入默认登记引用、类型、大小与必要索引；后续按范围读取。文本支持真实有界读取，目录分页，图片按任务选择预览与局部裁剪。批次图片不全部内联。
- TIFF/正射/多波段数据先读元数据、波段、坐标与统计，模型视觉只接收必要预览；原像元计算仍在专业工具中完成。
- 分开记录请求体字节数、文本 token、视觉 token、工具定义、输出预留及估计误差。base64 传输长度不能直接当作视觉 token。
- 优先使用与当前模型权重和聊天模板匹配的本地 tokenizer/处理器；若不可得，采用标明不确定性的保守估计及同配置已有 usage 校准，不能统一除以 4。没有数据记未知，不记实际 0。
- 超预算优先减少重复指令、替换旧大工具结果为可追溯引用、保留最近必要消息和工具调用配对。复用 Harness 现有压缩能力，避免第二套压缩器。
- 工具定义若确实构成主要开销，再实行稳定能力目录与按需加载；常用读写工具保持可发现，能力加载不改变已确认权限和预算。
- 不增加逐轮思考摘要调用。若现有上下文压缩需要模型摘要，单独计费/计时/计预算，只在触发阈值时执行，并保留原始记录。

**改动入口：** `context.py`、`agent.py` 的上下文 hooks、现有输入/视觉工具、`MessageAttachments.tsx`/`SourceBrowser.tsx`。

**出口：** task11 原目标能进入模型并完成必要读取，不再被错误字节计量阻断；批图选取不丢附件身份，下一轮未选取的图片不重复内联。真实输入成本与估计有可解释对应。

### D3：执行、累计预算、恢复与删除

**用户新增可用流程：** 提交计算→查看进度→停止或重启→确认原作业状态→继续读取成果；删除会话后所属文件与作业不复活。

- 用实际运行账号与配置检查执行器能力，失败明确返回原因。修复或启用已认可的执行路径；不能绕过操作系统/环境策略，也不能悄悄改宿主机执行。共同执行器故障出现后暂停依赖它的模型试次。
- 模型请求/动作在开始前原子预占预算，完成后结算；父任务与子任务累计，追问和重启不重置同一次研究试次。持久 deadline，不能只依靠客户端轮询。
- 研究上限沿用 12 请求/30 动作/900 秒；这是研究试次上限，不能机械套到长时间 ODM 产品作业。正式作业有独立声明的时间与资源限额。
- 重试仅用于明确瞬态错误，在剩余预算内最多两次重试；鉴权、权限、上下文契约和确定性输入错误不盲重试。重试仍记原试次，不改目标重建。
- 长作业保留现有 Job ID 和 tool_call_id；重启核对外部执行状态，已成功的计算直接接回结果；无法确认是否产生副作用时先核对，不再次执行。
- 区分“请求停止”和“执行已停止”。取消、预算耗尽、不可恢复错误均需核对排队/运行中的关联 Job；重启不得自动启动已取消队列。
- 删除沿用现有实现补齐竞态：先持久标记删除并阻止新写入，终止所属作业，再清理上传副本、中间/最终产物、缓存、索引、模型记录及会话专属容器/日志。清理失败可重试且状态可见。
- 用户提供路径所指向的外部原始文件只移除引用；共享缓存按归属/引用计数处理。删除会话不应删除用户源目录或其他会话数据。残留回调不能重建已删除会话。

**改动入口：** `jobs.py`、`sessions.py`、执行器适配、持久状态及任务控制 API、`research_run.py`；不新建平行队列。

**出口：** 一个受影响作业完整经历取消或重启恢复，不重复计算；研究预算跨追问有效；用专用可删除夹具确认清理闭合及外部源文件保留。复用现有删除证据，只补竞态/新增资源类型。

## 6. 最小契约补强，避免过度设计

优先扩展现有结构与事件，不为每个概念新建服务。

| 契约 | 必须能表达的事实 |
|---|---|
| 请求事件 | 会话/轮次/请求关联、事件序号、原始或重放来源、阶段、结束原因；工具/Job 标识按需携带 |
| 生效配置快照 | 模型标识、服务与上下文、thinking、输出上限、工具/指令摘要、代码/配置版本；请求使用同一份快照 |
| 预算记录 | 累计已用/预占、持久截止时间、父子关系、触发停止原因；重试也计入 |
| 试次记录 | 唯一 ID、输入与目标摘要、版本、触发原因、干预、结果、失败层、评分规则版本、人工裁决；不可覆盖 |
| 数据归属 | 会话拥有的副本/产物与外部源引用区分，关联消息/Job，删除状态及待清理项 |
| 上下文计量 | 实际/估计/未知、各组成项、计量方法和适用模型配置；不将字节和 token 混写 |

兼容策略：新增字段可选并逐步补齐；旧数据未知项保留未知。不能为了统一字段重写历史试次或改变历史失败身份。

## 7. 执行纪律与停止条件

每项工作开始前写下：**触发原因、受影响行为、复用证据、预期改动、一次验证的停止条件**。没有新触发就不重测。

实现顺序以新版实现指导为准：先贯通模型流与一个文件工具，再补上下文和已有科学 Jobs。历史证据纠正可以独立进行，不把全部账本整理设为用户流程开发的前置关卡；共同模型服务或执行器阻碍未解决前，不继续制造下游失败试次。

- 同代码、目标、输入与配置已有失败：先检查记录；没有新的修复或条件变化，不再运行。
- 文档、oracle、评分变化：只重评旧记录，不重新推理/计算。
- 流解析、状态、预算、清理等工程边界：优先确定性模拟；不把每个分支都交给真实模型验证。
- 真实模型验证：仅用于受影响的完整流程，达到该交付出口即冻结。出现新的失败只修受影响项。
- 科学计算：已有正确成果直接复用；任何新增计算必须说明未被已有结果回答的具体问题。
- 源码研究：每个阻碍只产出“本地缺口→参考函数→采用/不采用→验证条件”。证据足够就进入实现，不持续扩展阅读仓库列表。

**第一项实际开发交付：** 完成 D0 中请求关联、只读诊断和生效配置一致性，接着交付“原生思考/正文可见，停止后可以继续发送”的 D1 流程。上下文修复随后承接已有真实科学成果读取。当前主阻碍为计量与诊断不可信、执行器可用性、预算/恢复闭合及科学裁决不足；尚不能据此承诺阶段 2 已完成。
