## 1. 产品目标与范围

完成一个供用户持续使用的本地通用 Agent：通过自然语言交流，自主选择文件、文档、图像、代码、知识及专业计算能力；能够处理长任务、接受后续要求、观察真实执行状态、恢复已有工作并交付可用结果。正射多光谱拼接与 PROSAIL LAI 是当前专业主线，也是检验通用运行机制的真实场景。

原始依据为 [项目开发文档](../../forestry-uav-agent-project-book-zh.md)，实施范围按用户后续决定更新：

- 保留通用文件/文档/代码/数据处理、已有知识与显式记忆、原生思考、按需计划、专业工具、恢复、清理、一键入口等目标。
- 点云后续开发暂缓，已有正确成果与功能保留；Agent 联网搜索、领域峰值资源/吞吐评估取消。开发者查阅源码不等于重新启用产品联网搜索。
- 正式模型/harness 比较、配对、消融、留出评估及阶段 3 安装发布工作继续保留，当前不提前展开重复实验。
- 具体测试和用户会话是发现问题的样本，不替代产品需求，也不自动变成全部重跑清单。修复必须适用于同类任务，不能围绕一句提示词或一个影像目录写特例。

## 3. 技术路线：完成职责分离，必要时替换驱动

继续采用“可替换运行核心 + 现有服务适配”的路线。Python/FastAPI、现有前端、SQLite、Qwen/Ollama 和科学执行环境先继续使用；不因参考 TypeScript/Rust 项目就整体迁移语言与数据。

```text
UI / API
  → AgentRuntime：领取消息、驱动模型与工具、结束本轮
      ├─ ModelAdapter：模型请求与原生内容流
      ├─ ContextBuilder：本轮消息、工具、设置与计量
      ├─ ToolRegistry / 执行通道：定义、校验、动作、结果投影
      ├─ JobExecutor：后台执行、观察、取消、恢复与重试
      └─ SessionRepository：会话事实、消息与事件提交

文件 / 文档 / 图像 / 代码 / 知识 / Imagery / PROSAIL
  → 注册能力并依赖所需服务，不反向依赖具体模型循环

现有 Store / Resources / Jobs / 科学 Worker
  → 作为接口实现继续复用
```

这些是职责边界，不要求每项新建一个包或服务。沿用框架能正确提供的类型、工具结果配对和恢复机制；不额外叠加第二套模型循环、作业队列或压缩器。新增功能应通过注册能力和必要的执行实现接入。

若现有驱动必须依赖持续叠加的私有 hook、双份状态写入才能满足这些契约，可以替换 `AgentRuntime` 驱动。决定依据是具体无法满足的行为及调用点，不是文件长度。替换时保留适配接口、旧数据和正确成果，同一会话只由一个驱动接管；旧框架内部检查点不能无损迁移时先结清旧活动，再从已提交历史续聊。

## 5. 需要完成的实现

### 会话与上下文：一起接通 Repository 和 ContextBuilder

主要入口：`agent.py::run/durable_task_facts`、`context.py`、`conversation.py`、`store.py`、`vision.py` 和现有 `runtime/`。

1. 以会话的已提交用户消息、工具事实和活动记录生成上下文。禁止仅继承最后一个 `completed` 回合，从而跳过失败、暂停或取消回合中的用户指令。中断生成的正文前缀保留中断标记；未完成工具需明确结清或作为待处理调用恢复，不伪造成功。
2. 区分原始目标、后续指令和当前活动。作业记录关联发起消息、操作类型、可读名称、输入、状态与结果；追问可以定位当前或最近相关活动。多项活动确实存在歧义时再询问，不用固定关键词匹配“完成了吗”。
3. `PreparedInput` 同时包含实际发送的 messages/tools/settings 和 text/vision/tool/framing 分项计量，明确实际、估计或未知。优先使用适配模型模板的 tokenizer/图像处理参数；缺少时标明估计，不能把 JSON、UTF-8 或 base64 大小当模型 token 实耗。
4. 历史裁剪、指令、工具定义或模型配置变化后重建相应计量；usage 锚点只用于满足身份条件的估计，避免重复叠加历史成本。纠正视觉用量为零却归因图片过大的错误。
5. 上传与发送只建立消息附件、来源身份及必要元数据。批量图片先索引再选择读取，文档按范围读取，科学 TIFF 主要通过栅格工具访问。已需要的视觉内容按当前问题保留，不能每轮全量重发，也不能无条件全删。
6. 压缩保留当前指令、未结清活动、关键错误和有效读取引用；工具调用/结果按 ID 配对。读取内容退出窗口后，应优先通过保留的引用和范围找回，避免反复枚举全部输入。
7. 所有状态变更与相应事件在同一事务内提交，提交后通知 UI。框架步骤快照负责恢复驱动执行位置，应用仓库负责消息、作业和资源事实，明确二者职责，避免各自覆盖最终状态。

完成表现：普通问答、文件/批图、多步骤任务在中断或压缩后仍能承接用户要求；输入预算错误能够指出实际组成；无需用户理解内部 ID 或手动修订。

### 工具执行与无进展控制：用事实驱动，不比较包装文本

主要入口：`runtime/tools.py`、能力注册文件、`agent.py::perform/guarded_tool`、`progress.py`。

1. 继续迁出图像、文档、代码和专业能力。一份定义派生模型 schema、执行路由和结果投影；保留现有准入、权限和动作记录的唯一执行通道。能力缺失返回明确原因，不让模型通过重复调用探测同一个已知缺口。
2. 固定处理顺序：参数校验 → 权限/取消/预算 → 动作登记 → 执行 → 结果校验与事实保存 → 进展判定 → 模型内容和 UI 投影。对框架已包装的结果保留原始结构化引用，不能靠解析截断文本判断进展。
3. 将稳定的输入身份/版本、读取范围、实际结果、失败类别、作业状态变化用于判断；动作 ID、时间戳、新句柄和无关资源波动不算任务推进。资源从不足变为满足准入是相关变化，不能一概忽略所有环境变化。
4. 同时识别相同请求重复、同一错误反复尝试，以及不同工具围绕同一未改变障碍循环。按活动维护有界的无进展观察，成功读取另一份必要文件或取得新的页段仍可继续，不用“最多几个工具”粗暴限制正常任务。
5. 对可纠正参数返回准确要求；瞬态故障在原预算内有限重试；确定性输入错误需改变相关条件后再试。没有输入且工具已确认时，直接提出缺失项；已获得足够事实时直接回答。新用户消息不自动重置同一活动的累计预算。
6. 上下文恢复允许读取被移出的必要内容，但不能因每次压缩都重置无进展判定。恢复只是找回旧事实，和外部任务进展分别记录。
7. 工具默认串行；明确只读且并发安全的工具才有界并行。修改和计算提交走独占边界。取消后不再启动新调用，已启动调用记录真实结果或停止待确认，保持消息配对。

完成表现：常规问答不强制计划/诊断；需要工具时能自主调用；异常能解释或有依据地恢复；相同事实与错误不会靠更换包装持续消耗模型请求。原生思考继续展示，不增加总结模型或隐藏重复来冒充修复。

### 后台作业、恢复与清理：完整接入现有 Jobs

主要入口：`jobs.py`、`imagery.py`、`imagery_resume.py`、`imagery_worker.py`、`sessions.py` 和对应 API。

1. 给所有长作业统一登记名称、类型、来源消息、逻辑活动、调用/尝试、状态、时间、日志、结果和恢复关系。扩展现有数据结构，不新建平行队列；旧记录缺字段标未知，不猜历史事实。
2. 提交返回 JobRef。短时等待到期返回“仍在运行”，释放对话；模型可选择等待或继续其他交流，应用观察不依靠反复调用模型。作业终态通知进入同一会话的串行处理路径，按事件身份去重，避免后台通知和用户消息并发改写历史。关闭网页不影响已登记计算，重连接回状态。
3. 模型请求、轮次等待与作业执行分别设定时限。作业上限由操作配置和资源约束制定，不由模型随意猜一个短秒数。超过真实执行上限仍须停止并报告；不能以无限运行代替预算控制。

| 控制事件 | 必须采用的作用范围 |
|---|---|
| 模型单次请求超时或模型调用预算耗尽 | 停止对应模型活动，记录原因；不自动终止已登记、拥有独立执行预算的后台任务 |
| 单次等待结束 | 返回真实作业状态；计算继续，不能伪报失败或成功 |
| 用户停止当前回答 | 停止当前轮次派发；已移交后台的任务继续可见，用户可单独停止；同步工具结清状态 |
| 用户取消后台任务/整体活动，或删除会话 | 明确取消所属作业并阻止其排队实例启动；实际退出确认后才记停止 |
| 作业达到自身时限或资源硬边界 | 终止该作业，保留失败诊断和可恢复材料 |

上述范围替代旧计划中“取消/预算耗尽统一停止所有关联 Job”的笼统要求。

4. 将调用重放幂等、运行中接回、成功成果复用和失败重试分开。重放同一次提交不得重复创建；相同计算正在运行则接回；成功且输入/方法/环境匹配才复用成果；失败不能因为代码相同就当作新提交成功。
5. 用户明确要求重试且具备修复条件时，创建关联原作业的新尝试，保存原因、参数/预算差异和恢复点，不要求用户额外重建会话。失败现场具备恢复条件则优先恢复；没有新条件且相同失败已确定时说明阻碍，不自动反复重算、不通过新 ID 重置累计预算。
6. 先保存 Worker 的实际处理日志、错误和必要检查点，再清理容器及可再生暂存。ODM 的 `processing.log` 不能仅因不在容器标准输出中就丢失。进度来自实际阶段事件/日志，只有能计算时才给百分比。不能只显示一个永远转动的等待标记。
7. 保留策略区分已验证成果、必要恢复材料、短期诊断与可删除缓存。失败恢复材料提供容量/期限配置和可见清理结果；过期后如实说明不可恢复。已有正确结果不因修报告重新计算。
8. 删除继续采用持久删除标记：冻结新写入 → 停止所属活动 → 清理会话上传副本、产物、恢复材料、索引及日志 → 提交删除完成。覆盖迟到回调、重复删除和清理中断。外部路径原文件只移除引用，共享材料按归属处理。

完成表现：任意接入的长作业都能登记、观察、追问、取消、恢复或解释失败；聊天状态和计算状态不互相冒充；任务重启不重复产生副作用，删除不留下会话专属运行资源。

### 交互与能力展示：统一呈现底层事实

主要入口：`App.tsx`、`JobsPanel.tsx`、`SourceBrowser.tsx`、消息组件、样式和 `attachments.py`。

- 右侧增加独立、可折叠的“后台任务”区域，不依赖诊断开关。展示当前会话的名称、状态、耗时、实际阶段、结果和停止操作；日志与资源细节折叠。与模型按需生成的 Plan 分开。
- 文件/文件夹统一使用现代系统选择体验，支持盘符、地址栏和网络位置。替换旧式目录树选择入口，保留拖入和粘贴路径。核对选择器进程的用户身份和映射盘可见性，不能把看不到 N 盘简单归为前端问题。大目录保持引用，不整目录复制上传。
- 用户消息统一右侧有色气泡，Agent 左侧；首条与后续消息使用同一消息组件。正文与输入区采用易读字号，默认 15–16px，附件随对应消息显示，待发送附件只在发送前出现。

## 7. 执行与验证方式

接续位置是已完成的模型适配和文件工具迁出之后：**先把 ContextBuilder 与 SessionRepository 接到现有真实调用路径，随后完成工具执行与 JobExecutor；界面依据稳定事件契约接入，最后完成科学报告和主入口收口。** 这是实现依赖，不是要求逐张任务卡串行审批。诊断与报告纠错可在不争用代码/运行资源时推进。

只有在框架能力无法满足契约时重建驱动；每迁出一项职责，删除对应旧实现或保留单向兼容转发。不得长期让新旧机制同时修改同一会话。

验证前记录触发原因、影响范围、可复用证据和停止条件。优先离线记录/受控执行器验证状态与副作用，再用真实模型验证需要模型判断的接缝；不能用简单问答代替原失败类型。验证通过且后续无相关变化即冻结，不默认全量回归、不重放整个历史任务库。

| 用户流程 | 本轮开发完成后需证明的行为 | 可复用与停止条件 |
|---|---|---|
| 连续交流与停止续聊 | 普通回答、任务修改、中断、暂停后追问均正确承接，刷新后状态一致 | 复用流与停止前缀证据，只补历史/队列受影响路径 |
| 文件、文档和批图 | 常规选择/路径输入，按需读取，计量可解释，附件不重复全量入窗 | 复用真实读图与索引证据，补原预算失败及批量读取接缝 |
| 工具异常与多步骤任务 | 确定性错误不循环；纠正后能推进；不同有效读取不误停 | 先用本次轨迹和结构化结果离线验证，再做必要真实模型检查 |
| 后台执行 | 提交、等待返回、继续交流、追问、终态通知、失败恢复/重试语义正确 | 受控长作业验证通用机制；真实专业接缝只在有改动触发时验证 |
| 恢复与删除 | 重启接回不重复提交；取消确认；清理中断可恢复，外部源文件保留 | 复用既有证据，新增资源及竞态用专用可删除夹具验证 |
