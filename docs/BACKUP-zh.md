# 离线备份与原位置恢复

本流程保存应用数据库、原生模型检查点数据库、上下文/知识快照、会话密钥及任务文件/不可变产物/封存清单。它备份配置工作区内的`.forestry`和`tasks`，不执行其中的代码，也不启动模型或Worker。备份分类为私密，包含原有私密数据与本地会话身份。

源码、Python环境、配置文件和工作区外原始数据由原部署保留。本命令是应用状态与产物备份，不是跨设备完整部署迁移。登记来源在清单中保留身份/版本及是否纳入副本；原始数据是否仍可用且未变化会单独报告。恢复不会改写资源权限、原始版本或绝对路径；来源缺失/变化时应重新登记并明确修订任务，不允许绕过版本保护。

1. 暂停任务并确认实际Worker已停止或完成、未决动作已对账，再停止对应配置的本地服务。仅关闭浏览器不会停止服务或Worker。
2. 保留原配置，在项目环境中创建一个独立新备份目录：

```powershell
python -m forestry_agent.cli backup create --config config/app.local.yaml --path backups/20261012-v1
python -m forestry_agent.cli backup inspect --config config/app.local.yaml --path backups/20261012-v1
```

`--path`必须在运行工作区之外；create拒绝已有目录。输出包含清单SHA、文件数量/字节、来源状态及`workspace_root`。SQLite使用原生backup API合并已提交WAL内容，并持有写锁；会话、检查点和任务产物按大小/SHA核对。仅排除两个内部SQLite数据库的临时sidecar，任务产物即使名为`.sqlite`或`.sqlite-wal`仍按普通文件保存。

数据库副本归一为独立SQLite文件，检查使用immutable只读连接，不创建WAL/SHM缓存，不读取注入的事务文件。副本出现非空内部WAL/journal时拒绝；早期检查留下的空WAL/SHM不被当作应用数据。修正后对同一成功副本只读核对，文件集合/字节/mtime完全不变，证据`backup-inspection-readonly-20261012-v1.json`；没有再次备份或恢复。

3. 恢复前保持服务停止，释放所有SQLite连接。按输出的原`workspace_root`核对路径，将原`.forestry`与`tasks`移动到独立保留位置；不删除原数据。若任一目录仍在原位置，restore拒绝覆盖。
4. 用同一配置及原工作区位置恢复：

```powershell
python -m forestry_agent.cli backup restore --config config/app.local.yaml --path backups/20261012-v1
```

先检查完整清单和每个文件，再复制并复核到新暂存目录，先发布任务产物、后发布数据库。命令成功后服务仍停止，任务原状态保留，没有自动推理、计算或继续副作用。检查来源状态后按原启动说明运行服务；暂停任务应由用户明确恢复。

监听地址无法独占、活跃任务/Worker/角色、排队回合、未决动作、未封存交付、损坏数据库/清单/文件或不安全链接都会阻止备份/恢复。操作失败保留已有副本和暂存文件，不自动清理或覆盖；失败备份没有完整清单，不能作为恢复源。恢复中断时保留原目录副本，根据已发布目录和暂存记录处理，不能直接启动半完成的工作区。
