# Revised implementation baseline · 1.9

This is an independent implementation, with no reuse or migration of the legacy ForestryUAV-Agent runtime. The supplied Chinese project book remains the requirements source. The Chinese revised baseline records implementation amendments and is authoritative for this revision; this translation shares that revised baseline's version.

On 2026-10-06 the user deferred Agent network-search development. Keep existing implementation and safety boundaries, defer new search work and acceptance, and prioritize the local general agent. Search gates are marked user-deferred rather than passed and do not block this local delivery. The remaining stages, domain workflows, evaluation and scale requirements remain in scope.

R01–R16 and U01–U08 remain in scope. Deliver the complete general agent and usable local developer UI before implementing the two real forestry workflows, followed by the six-arm evaluation, lower-resource validation and real input-scale testing of at least 100 GB. Early domain compatibility and public-data feasibility checks are permitted, without implementing domain features early.

Keep persistent role definitions and delegate only when isolation or independent work helps. Internally checked products without field truth are acceptable with explicit support and limitations; they do not establish external accuracy. A green vegetation proxy does not satisfy a required canopy metric. The user selects lower-resource hardware after the pilot; full V1 remains incomplete until it is frozen and measured.

Use one PydanticAI/Harness loop, native history, persistence and compaction. Application SQLite remains authoritative for tasks, grants, actions, jobs, evidence and acceptance. Persist an action/attempt before its effect. Ordinary messages do not revise the task specification; amendments do. Validate candidate products before acceptance, seal the final manifest and publish recoverably before the terminal task commit. A manifest does not recursively hash itself.

Use spatial_support_ref consistently. Implement only real external/persistent boundaries, without one repository or service for each record. WP describes implementation, AC describes acceptance and DOM maps to WP. Share execution, resources, events, verification and delivery between general and domain features.

Private-derived network payloads require scoped authorization. Public fetch rejects private/loopback destinations and unsafe redirects. HTML previews isolate scripts and network. Reject extra fields at control boundaries, keep sources read-only, issue user grants only through authenticated human routes, and confirm worker termination before final cancellation.

Freeze max_unchanged_decisions for new tasks. Persist observations per task revision, logical user turn and role across native runs and restarts. Repeated observations, failures and empty end-of-file windows stop with NO_PROGRESS when the limit is reached, preserving confirmed effects. Resume does not reset the counter. Authenticated corrective input may stop the old turn and start a new corrective turn, without resetting task-level budgets; changes to objectives, inputs, methods or constraints still require amendment. Novel observations do not establish semantic acceptance.

TaskConstraints.allowed_capabilities is a unique list of registered capabilities. Omission or null inherits configured ceilings; an empty list denies every registered action. Explicit scope constrains native tool discovery, execution, job submission/start and delegated role intersections. Ordinary messages and models cannot expand it. Native overflow readers only access this run's existing tool results and grant no new source, network or execution authority. Amendments omitting constraints preserve the previous scope; explicitly submitting {} inherits configured ceilings. The UI revises objectives, inputs and scope, pauses old execution, and requires reconciliation before resume.

Amendments retain unchanged output preferences, requested metrics and frozen fields. Control retries only return their original receipt. Pause/amendment/cancellation retries cannot cancel a newer run token; resume retries cannot create a new model turn.

Optional project-owned WSL Docker transport fixes the distribution, explicit guest Unix socket and private client configuration, removes host credentials/proxies/WSLENV and uses guest env -i. Convert authorized absolute local drive mounts only; reject UNC/relative paths and do not reset existing Docker/WSL data. Lock the signed rootfs, guest packages and immutable Python image separately. Generated code still uses the same Jobs controls, identities and resource limits. Terminal wait_job results include real bounded diagnostics for debugging.

Startup reconciliation events record specification revision, logical turn, prior status and blocker code. Reinject the application record into that same turn after resume in H0/H1/H2; do not forward parent records to assignments. Other tasks, revisions, turns or legacy events without an explicit turn are not current recovery facts. The startup record alone does not prove process interruption, container survival or correct computation; these require independent execution evidence.

Scoped dependency preparation reuses Jobs, actions and immutable artifacts through environment.prepare. This increment installs explicitly authorized offline wheels inside restricted containers, resolves transitive dependencies and checks pinned hashes, without changing host packages. Reuse binds the current task/revision, successful preparation job, archive hash and actual image identity. Roles require explicit environment-artifact grants. Failures do not silently change platforms or disable dependency resolution. Agent acquisition and source builds remain pending; developer fixture downloads are not evidence of autonomous dependency acquisition.

H1/H2 root instructions expose the last 24 registered artifact names/IDs and the latest eight jobs from this task revision, with at most eight artifact IDs per job. Failed/timed-out diagnostics copy only the last 512 UTF-8 bytes of an already confirmed terminal job.observe receipt, retaining its source action and truncation flag. Recorded status is not a fresh execution observation or acceptance. No additional executor probe, file body, generated code or environment manifest is injected. H0 omits this auxiliary metadata; assignments do not receive parent metadata. An initial request exactly equal to the objective retains the complete text once with an explicit equality flag; different follow-up requests remain complete and separate.

Tool schemas are discounted only when the native positive-usage response is bound to a measured, covered request receipt with matching response-content hash, task, turn, revision, assignment and exact current schema hash. Missing usage, legacy receipts or changed scopes/content/schemas retain the full conservative schema margin. Native history/checkpoints, hard context limits, output reserves and the actual-usage-over-estimate stop remain intact. The native tiered compaction target changes from half to three quarters of available input budget (21,504 for 32K context/4K output). This calibration does not establish long-task or small-model quality.

H1/H2 reuse native Planning with write_plan/read_plan only when task and role allow task.plan; H0 omits planning tools. The native table resides in the existing SQLite database, scoped by task, revision, logical turn and assignment. Bound plans to 16 steps/8192 UTF-8 bytes, 500 characters per content, 64 per ID and one in-progress step. Reads/writes use existing action journals, permissions and cumulative budgets. Model plan changes are not new execution evidence and cannot reset no-progress counters. Plans remain model_proposed/not_assessed, without changing objectives, grants, methods, acceptance or terminal state. Current native compactors rebuild requests from durable history and drop wrap-stage reminders. A small compatibility adapter invokes the native ephemeral injector in the before-model chain after compaction and before budgeting/snapshots, without adding reminders to history. Old frozen role catalogs do not automatically acquire the new capability.
