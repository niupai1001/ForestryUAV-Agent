# 通用 Jobs 的资源准入与输出预算

任务创建时将 CPU、RAM、输出上限写入 `config_snapshot.execution_limits`；每个 Job 保存 `resource_request`，队列重试与服务恢复复用原预算。旧任务未存此快照时，在新 Job 提交时冻结当前上限。历史已启动 Job 不补造输出限额或原容器配置证明。

当前生产后端为同机 WSL Docker。准入读取宿主机可用 RAM、指定 WSL 的 `/proc/meminfo` 和在线 CPU、工作盘空闲空间。RAM 须同时满足宿主机和执行机读数；要求为容器上限加保留量。磁盘要求为两份输出预算（工作输出、不可变产物副本）加保留量和 16 MiB 元数据余量。临时盘计入容器 RAM 上限，不另充作磁盘空间。有效 CPU 为请求上限和执行机在线 CPU 的较小值。通用执行器暂不挂载 GPU，VRAM 请求为零。

`max_code_output_bytes` 默认 512 MiB，`code_memory_reserve_bytes` 和 `code_disk_reserve_bytes` 默认各 1 GiB。用户配置保留量可以改变下一次准入决策；已有 Job 的执行上限不变。资源不足保持同一个 queued/creating Job，等待原因、预算和政策未变时不重复产生事件；恢复准入清除旧等待提示。原任务暂停、取消、修订和权限边界继续生效。

在容器 Python 入口设置不可提升的 `RLIMIT_FSIZE` 硬限制，子进程继承；该限制约束单文件，包含临时盘文件。既有 worker 每轮检查输出文件数量和合计大小，超限或工作盘低于保留量时保存停止意图，核对原容器 ID/标签后停止，并确认停止后记录失败。已退出但超预算的 Job 同样不封存为成功产物。总输出监测不是文件系统硬配额，轮询间隔内可能超预算；不承诺其他进程的并发写盘无法耗尽空间。

计算成功后还检查封存副本所需磁盘空间；不足时保留 collecting 状态，恢复后继续同一个 Job。已封存文件不再次计入复制需求，原幂等产物导入继续适用。工作台“作业”页显示原预算、准入快照、等待或停止原因及真实状态。

WSL 探测失败返回明确阻塞，不用 Windows 空闲 RAM 冒充 Docker Desktop 虚机可用 RAM。当前 Docker Desktop 虚机准入探测器尚未实现；本阶段已验证后端为 WSL。Linux 同机后端使用本机读数，未验证远程 daemon 的准入；不得据此声明远程执行支持。

证据：`admission-tests-20261010-v1.xml` 首轮 25 通过、1 断言失败（接口现有验证错误为 400，断言误写 422）；v2 只复核该断言，1 通过。共有 26 项不同检查，不将重叠批次累计为 27 项。夹具读数和 Docker 故障测试不能证明真实执行。

`admission-real-20261010-v1.json` 记录实测 WSL/宿主机读数与两个真实断网、非 root、64 MiB/2 CPU 作业。第一项提高配置保留量触发等待，再恢复正常保留量，同 Job 完成并验证单文件硬限制、不能提升限额、子进程继承及产物 SHA。第二项 1 MiB 总输出预算实际产生 1.5 MiB，确认原容器停止、失败且未生成产物。保留超出部分，不能把此结果写成“硬总配额”。两个自有终态容器核对后移除；原 Job/产物/evidence 均保留。

这些检查关闭了实测准入与输出监测的实现缺口；未开启模型，没有证明原生 Agent 在资源压力下的完整交互，也不代表真实低资源设备、GPU准入、物理资源耗尽恢复或 ≥100 GB 数据验收。后续按阶段门禁补证据，Agent 联网搜索仍暂缓。

新增作业页的真实Edge浏览器核验 `admission-ui-20261010-v1.json` 单项通过，只读上述原Job的成功/失败、不同冻结预算和准入快照；390px布局、无横向溢出/JS错误及截图已检查。生产重载前后保护记录 `admission-pre-reload-20261010-v1.json`、`admission-post-reload-20261010-v1.json` 确认实现加载、原暂停队列/试次文件保持，未再次执行旧作业。
