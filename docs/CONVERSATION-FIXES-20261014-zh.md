## 已确认原因

最终输出 `summary` 与“仅总结”提示混淆了回答正文和摘要；模型先写完整正文后又返回摘要，应用仅保存了摘要。取消被当成会话终态，图片只有文件记录而没有视觉内容。Markdown未渲染；附件持续显示全部会话输入。应用已配置32K/预留4K输出，计量在输入版本变化后无法复用同一响应的已计费工具与指令记录，出现重复保守计入。出错附件实际为约1.2 KB的AGENTS.md，文件内容不是超限原因。

实际部署的Ollama 0.40.2使用兼容接口。旧代码向该接口发送的原生`think`和`options.num_ctx`字段不生效；本地查询证实大模型加载窗口为262144且默认推理档为medium。已用兼容接口支持的`reasoning_effort=none`落实原来关闭内部推理的配置意图。应用32K上限与后端实际窗口是两个事实，本轮没有改模型权重、服务参数或放大应用上限。

## 本次结果

| 用户问题 | 修正后的行为与原理 |
|---|---|
| 1. 概括取代回答 | 普通文本直接作为完整回答；旧结构化接口为检查点兼容保留。若同一响应同时包含正文与摘要，保留公开正文。能力事实由应用当前工具及本地模型能力提供，不能把Qwen家族能力当应用功能。 |
| 2. 看不到过程 | 显示本回合实际工具步骤与公开进度；保存由动作回执生成的简短处理说明。原生内部逐字推理不展示，未伪造推理内容。 |
| 3. 后续消息叫补充 | 改为“你”；连续多轮消息依次处理，输入不因一次回答完成而关闭。长会话打开/新回复自动定位最新消息，用户向上阅读时保持位置。 |
| 4. 取消后不能发送 | “停止”结束当前执行，确认停止后可在同一会话再发送。暂停阻止后续动作，已启动Job继续运行；继续恢复已暂停处理。超时/上下文错误后，新消息也能继续，旧失败和累计预算保留。 |
| 5. Markdown符号裸露 | 使用react-markdown及GFM渲染标题、粗体、列表、代码和表格；禁止原始HTML执行及自动加载远程图片。 |
| 6. 固定政策尾注 | 提示词取消复制固定尾注，普通对话的limitations为空；历史说明折叠保存。任务实际缺口仍应按需要说明。网页搜索与读取运行时关闭，审批不能将其开启；依赖下载审批与网页搜索不同。 |
| 7. 文件触发上下文超限 | 同任务、模型/权重及精确响应的已计费定义记录可跨输入修订复用，限于计量，不放宽资源权限。保留窗口限制、测量核验及输出预留。 |
| 8. 附件一直占输入框 | 输入框只展示待发送文件；发送后附件随对应用户消息保存。原文件长期保持引用，模型只收到名称/ID及按需读取片段；图片仅在本次发送或按需读图时传入，后续由原生历史与压缩管理。 |
| 9. 添加数据复杂 | 上传、拖入、选择文件/文件夹或明确给出本地绝对路径即可。应用自动授予该会话只读输入；文档、图片、工具输出中出现的路径不会授予权限。Agent可从已发送文件夹选文件用于作业，复用原目录授权，无需用户逐一登记。 |
| 10. 没有读图链 | 根据本地模型vision能力提供实际图像输入与view_image工具；能读当前会话图片产物。原图不变，解码/缩小预览以界定内存与视觉成本；不是仅发送文件名。 |

## 实际限制

上传单文件128 MiB；更大文件/文件夹使用本地引用。直接读图限制20 MiB、2500万像素，最长边缩至1024，动画仅首帧；一次消息先传最多两张图，其余按需读取。小文字或大型遥感影像应提供局部原清晰度裁剪/分块。图片理解不是完整地理空间或摄影测量处理，ROI/分块/ODM仍属于阶段2剩余开发。

系统原生文件/文件夹对话框未由自动浏览器操作点击验收。普通回答为生成内容，不能保证每次措辞完全一致；原有错误回复不改写。后端真实窗口和应用上下文保护分别记录，不承诺文件上传后全文常驻或无限会话。
