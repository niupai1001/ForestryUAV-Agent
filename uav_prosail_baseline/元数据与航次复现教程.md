# DJI 多光谱影像元数据与航次复现教程

这份教程针对 DJI P4 Multispectral/FC6360 原始数据，目标是回答三个问题：

1. `CaptureUUID`、GPS、RTK、辐照度、渐晕和畸变参数究竟在哪里；
2. 这些字段由什么硬件产生，是否经过后处理；
3. 下一次航飞后，怎样只用本地代码把它们读取、汇总并送入正射流程。

本教程中的读取脚本不会改写原始影像。原始目录应始终作为只读输入。

## 一、先建立正确的数据结构概念

一张原始 JPG 或 TIF 实际上同时装着三类内容：

- 像元矩阵：相机传感器记录的数值。P4M 单波段 TIF 是 16 位数据，原始值
  仍是 DN，不应直接称为反射率；
- EXIF：存放在 JPG/TIFF 内部的标准标签，例如相机、时间、曝光、焦距和
  标准 GPS IFD；
- XMP：同样嵌在文件内部的一段 XML。DJI 把 `CaptureUUID`、波段、辐照度、
  云台姿态、RTK 原始状态、渐晕和畸变参数等厂商扩展字段写在这里。

因此，EXIF 和 XMP 不是额外生成的两个文件，也不需要联网下载。它们在按下
快门时由相机、飞控、GNSS/RTK 模块和阳光传感器共同写入原始影像。

航次目录还可能有独立文件，例如 `Rinex.obs`、`Timestamp.MRK`、
`PPKRAW.bin` 和 `EVENTLOG.bin`。这些不是影像元数据，而是 GNSS 原始观测、
曝光事件和飞行记录。做 PPK 时必须保留，不能只留下照片。

## 二、`CaptureUUID` 在哪里，为什么能得到 77 组曝光

`CaptureUUID` 位于每张原始影像内部的 XMP XML 中，典型形式为：

```xml
drone-dji:CaptureUUID="92d161e9694a11ecb845961e120c629c"
```

它是一次同步拍摄事件的唯一标识。同一次快门产生的 RGB JPG、Blue、Green、
Red、RedEdge 和 NIR 五张 TIF 共享同一个 `CaptureUUID`。下一次快门会得到
另一个 UUID。因此分组应以 UUID 为主，而不应只依赖文件名连续编号。

本航次顶层共有 462 张影像，读取后得到 77 个不同的 UUID；每个 UUID 对应
6 个文件，所以 `77 × 6 = 462`。首组为：

- `DJI_0010.JPG`：RGB；
- `DJI_0011.TIF`：Blue；
- `DJI_0012.TIF`：Green；
- `DJI_0013.TIF`：Red；
- `DJI_0014.TIF`：RedEdge；
- `DJI_0015.TIF`：NIR。

这六个文件共享：

```text
92d161e9694a11ecb845961e120c629c
```

## 三、EXIF 与 XMP 分别怎么读取

### 方法 A：使用本项目的 Python 脚本

进入代码库目录：

```powershell
Set-Location 'E:\Document\ChatGPT\林业无人机遥感agent开发'
```

读取一张 Blue 原始 TIF：

```powershell
& 'E:\UAV_WORKSPACE\runtime\python\Scripts\python.exe' -X utf8 `
  'uav_prosail_baseline\scripts\inspect_image_metadata.py' `
  --image 'E:\0730-多光谱正射(晴天飞行)\1_原始数据\1630落叶松\DJI_0011.TIF' `
  --output 'E:\UAV_WORKSPACE\jobs\manual_metadata\DJI_0011_metadata.json'
```

如果换到另一台电脑，没有这个虚拟环境，可先准备 Python 3.10 以上环境并安装：

```powershell
python -m pip install Pillow
```

然后把命令开头的解释器替换成 `python`。脚本输出五部分：

- `exif`：TIFF/JPEG 主 EXIF；
- `exif_sub_ifd`：拍摄时间、曝光和焦距等 EXIF 子目录；
- `gps_ifd`：标准 GPS 标签；
- `xmp`：DJI 扩展 XMP 字段；
- `important_fields`：关键字段及其确切来源。

如果要查看完整的原始 XMP XML，在命令末尾增加：

```powershell
--show-raw-xmp
```

### 方法 B：使用 ExifTool 交叉检查

安装 ExifTool 后，可先列出全部标签：

```powershell
exiftool -G1 -a -s 'E:\path\to\DJI_0011.TIF'
```

只查看当前流程关心的字段：

```powershell
exiftool -G1 -a -s `
  -CaptureUUID -BandName -BandFreq -Irradiance `
  -GPSLatitude -GPSLongitude -RelativeAltitude `
  -GimbalPitchDegree -GimbalYawDegree `
  -RtkFlag -RtkSrcType -RtkStdLon -RtkStdLat -RtkStdHgt `
  -VignettingData -DewarpData `
  'E:\path\to\DJI_0011.TIF'
```

ExifTool 和本项目脚本都是读取器。它们没有“推测”这些字段，而是在解析
影像容器中的 EXIF IFD 和 XMP XML。

## 四、在本航次的一张影像里实际读到了什么

以 `DJI_0011.TIF` 为例：

| 信息 | 位置 | 实际值或状态 | 解释 |
|---|---|---|---|
| 相机 | EXIF `Make`/`Model` | DJI / FC6360 | 影像来源相机 |
| 时间 | EXIF `DateTimeOriginal` | 2022-07-30 16:29:44 | 需要另行声明时区，本流程按 UTC+8 |
| 尺寸与位深 | TIFF/EXIF | 1600×1300、16 位 | 单波段原始 TIF |
| 黑电平 | EXIF `BlackLevel` | 4096 | DN 信号校正需要 |
| UUID | XMP `CaptureUUID` | `92d...629c` | 同次快门六文件的分组键 |
| 波段 | XMP `BandName` | Blue | 当前 TIF 的相机波段 |
| 波段说明 | XMP `BandFreq` | `450(+/-16)nm` | 厂商原始字符串，原样保留 |
| 中心波长 | XMP `CentralWavelength` | 450 nm | 嵌套 `Camera` 标签 |
| 半高全宽 | XMP `WavelengthFWHM` | 16 nm | 仍不等于完整 SRF 曲线 |
| 经纬度 | XMP `GpsLatitude`/`GpsLongitude` | 42.40887284 / 117.31501691 | 十进制度 |
| 相对高度 | XMP `RelativeAltitude` | 75.14 m | 相对起飞参考点，不是冠层高度 |
| 云台角 | XMP `GimbalPitchDegree` | -90° | 近似垂直向下 |
| 辐照度 | XMP `Irradiance` | 8277.981445 | 已标定阳光传感器信号，不能直接当 W/m² |
| RTK 状态 | XMP `RtkFlag` | 50 | 厂商原始状态码，不擅自翻译为 FIX |
| 渐晕 | XMP `VignettingData` | 存在 | 原图未必已执行渐晕校正 |
| 畸变 | XMP `DewarpData` | 存在 | 镜头标定参数，不等于原图已去畸变 |

`BandFreq=450(+/-16)nm` 与单独的 `WavelengthFWHM=16` 是两个都应保留的
原始描述。不要只根据 `+/-` 的文字外观自行推导完整波段范围。用于 PROSAIL
卷积时，最佳输入是厂商或实验室给出的逐波长 SRF；仅有中心波长和 FWHM 时，
只能建立高斯或矩形近似，并在实验方法中明确记录。

## 五、这些参数分别由什么硬件产生

### 1. RGB 和五张单波段影像

P4 Multispectral 具有一台 RGB 相机和五台单色窄波段相机。一次拍摄事件会
形成一张 JPG 和五张 TIF。文件来自相机原始采集，不是后期软件从 RGB
“计算”出来的五个波段。

### 2. GPS、RTK 和姿态

经纬度来自机载 GNSS/D-RTK 定位解；飞控在曝光时把位置与姿态写入影像。
标准 EXIF GPS 通常是度分秒形式，DJI XMP 同时提供便于计算的十进制度。

RTK 要有差分改正源：可以是网络 RTK，也可以是 DJI D-RTK 2 基站。应用界面
显示 FIX 才表明当时获得固定解。若现场链路不稳定，则要用机载原始观测、
曝光事件文件和基站观测进行 PPK。

本航次还保留了：

```text
109_EVENTLOG.bin
109_PPKRAW.bin
109_Rinex.obs
109_Timestamp.MRK
```

它们说明存在 PPK/曝光同步材料，但并不能单凭文件名证明已经做过 PPK。
同理，当前 `RtkFlag=50` 只记录为厂商状态码。要证明绝对精度，仍需核对
飞行应用的 RTK 状态/日志、差分源、PPK 处理报告以及独立检查点误差。

### 3. 辐照度

机身顶部的光谱阳光传感器面向天空，记录拍摄瞬间的入射光变化；机腹多光谱
相机记录地物反射回来的光。阳光传感器的结果以 `Irradiance`、`SunSensor`
等数字写入每张单波段 TIF 的 XMP。

因此不存在五张独立的“辐照度影像”。本航次 385 张单波段 TIF 都带辐照度，
77 张 RGB JPG 不带，正好是 `77 × 5 = 385`。这些数值用于辐射一致性校正，
但只有 `Irradiance` 还不足以建立可溯源绝对反射率；科研实验最好同时拍摄
具有逐波段标定反射率证书的漫反射板。

### 4. 渐晕参数

镜头边缘通常比中心暗，这种空间亮度衰减叫渐晕。DJI 在生产标定中得到每台
相机的多项式系数，并写入 `VignettingData`。参数存在表示“可以校正”，不
表示原始 TIF 像元已经完成校正。

### 5. 畸变参数

`DewarpData` 含相机内参和径向/切向畸变系数，例如 `fx`、`fy`、`cx`、`cy`、
`k1`、`k2`、`p1`、`p2`、`k3`。它们也来自生产标定。SfM 正射软件通常会
联合优化相机模型，因此不要在不清楚软件行为时先手动去畸变再重复校正。

## 六、一次性提取整个航次

运行：

```powershell
& 'E:\UAV_WORKSPACE\runtime\python\Scripts\python.exe' -X utf8 `
  'uav_prosail_baseline\scripts\extract_flight_parameters.py' `
  --input 'E:\0730-多光谱正射(晴天飞行)\1_原始数据\1630落叶松' `
  --utc-offset-hours 8 `
  --output-dir 'E:\UAV_WORKSPACE\jobs\manual_metadata\flight_parameters'
```

这一步只扫描输入目录顶层。这样可以避免把“起飞前”“起飞后”的标定或测试
照片误并入正式航线。只有确认所有子目录属于同一航次时才增加 `--recursive`。

依次查看三个输出：

1. `flight_parameters.json`：确认 `image_count`、`capture_count`、相机型号、
   起止时间、位置、RTK 原始状态、辐照度数量和波段定义；
2. `capture_metadata.csv`：每个 `CaptureUUID` 一行，检查是否都有预期波段；
3. `band_metadata.csv`：核对各波段影像数、中心波长、FWHM 和辐照度中位数。

本航次的关键汇总为：

```text
image_count                  462
capture_count                 77
images_with_irradiance       385
images_with_vignetting       385
images_with_dewarp           462
camera_model              FC6360
```

若某次新航飞不是 `影像总数 = 曝光组数 × 每组文件数`，先检查漏图、重复复制、
未启用的波段或跨航次混放，不要立刻开始拼接。

## 七、下一次航飞怎样保证这些信息还能获得

### 航飞前

1. 使用原生多光谱拍照模式，并确认 RGB 与所需五个窄波段全部启用；
2. 清洁机身顶部的光谱阳光传感器，确保没有胶带、污物或附件遮挡；
3. 检查相机时间、存储卡和任务名称，记录当地时区；
4. 选择网络 RTK 或 D-RTK 2，确认差分链路可用；
5. 准备反射率板及其逐波段证书，不要只记录一个宽波段平均反射率；
6. 对森林冠层采用足够的航向/旁向重叠并保持近似垂直摄影；
7. 建立现场记录表，记下树种、物候、云量、风、起降时间、飞行高度和 RTK
   数据源。

### 航飞现场

1. 等待应用内 RTK 状态达到 FIX，再开始正式任务；
2. 起飞前拍摄无阴影、不过曝的反射率板，飞行结束后再拍一次；
3. 避免阳光传感器被人体、桨叶外附件或异物持续遮挡；
4. 云层快速变化时不要只依赖一次反射率板拍摄，要保留阳光传感器记录并在
   实验中标注光照条件；
5. 不要在任务中切换相机模式、波段组合或重新格式化存储卡。

### 航飞结束后

1. 复制整套原始目录，不要只挑选 JPG/TIF；
2. 保留 RINEX、MRK、PPKRAW、EVENTLOG、飞行日志和基站观测；
3. 不要先经微信、相册或普通图片软件导出，这些操作可能删除 XMP 或改变位深；
4. 按“地点_日期_架次”建立独立目录，不把不同日期、天气或高度混在一起；
5. 先运行单张元数据检查，再运行航次汇总；
6. 检查每个 UUID 的文件是否齐全，以及 `Irradiance` 是否缺失或为 0；
7. 元数据审计通过后再进入正射拼接和辐射校正。

## 八、从原始影像到 PROSAIL 的正确边界

当前代码已经解决“读出参数”和“生成几何正射影像”，但不能把 16 位 DN
自动等同于地表反射率。进入 PROSAIL 之前还需要：

```text
原始 DN
  → 黑电平、曝光、增益与个体差异校正
  → 渐晕/相机模型处理
  → 阳光传感器归一化
  → 反射率板定标（建议）
  → 五波段反射率正射影像
  → 按 SRF 对 PROSAIL 模拟光谱做波段卷积
  → 建立查找表/优化器/机器学习回归
  → 反演 LAI、Cab 等冠层参数
```

PROSAIL 是“给定叶片和冠层参数，模拟反射率”的正向模型。反演时观测量是
反射率，目标通常是 LAI、叶绿素含量 `Cab` 等参数，而不是“用 PROSAIL
把光谱反演成反射率”。如果输入还是 DN，应停在辐射定标阶段，不能直接做
PROSAIL 反演。

## 九、官方依据

- DJI P4 Multispectral User Manual：六相机、机顶光谱阳光传感器、D-RTK
  以及波段配置；
- DJI P4 Multispectral Image Processing Guide：`CaptureUUID`、`Irradiance`、
  `VignettingData`、`DewarpData`、黑电平、曝光和增益等字段的定义与处理关系；
- DJI P4 Multispectral Support：原始影像未预先执行渐晕/畸变校正，标定参数
  写在影像中；
- DJI 官方影像命名说明：每次拍摄生成 RGB/指数 JPG 与五张窄波段影像，
  相机编号 1–5 分别对应 Blue、Green、Red、RedEdge、NIR。
